# Proof-specific signature compilation

`EUNOIA_SPECIALIZED_RULES=1` selects an experimental checker. It is off by
default. The producer supplies a registry containing the generated compiled
rules used by the proof, with normal adaptive trace sharing. Helper-cache mode
takes precedence if both are enabled.

The same pinned Eunoia signature generates all 87 rule implementations. Each
has a kernel-checked, pointwise correspondence proof for every fuel, nil
resolver, primitive hook, type query, assumption and argument/premise vector.
The implementation record contains its source name, executable function and
correspondence proof. Registry lookup compares that name with the actual source
rule. Missing entries use the original interpreter. Duplicate or unrelated
entries cannot change a source result. No function-extensionality axiom is used.

Rule preparation uses one statically selected rule. Its requirements and
conclusion are compiled into Gallina expressions with statically resolved helper
calls. Each rule refers only to the helpers in its dependency closure; the
producer obtains record constants from a name encoding without evaluating a
global table of implementations. The three proved adapters preserve the original
flat, scoped and shared trace formats, root/premise/result bindings, scope
liveness, validation of unused steps, and separate SMTCoq semantic gates.

The generator can retain reference evaluation for selected helpers. The current
experimental policy retains `$run_evaluate`, following slower focused profiles
with all 59 helpers compiled. This policy changes computation strategy and has
its own generated correspondence proof; it changes no source rules or coverage.

```sh
python3 tools/eunoia/generate_specialized.py \
  --reference-program '$run_evaluate' \
  --output /tmp/CpcSpecialized.v --manifest /tmp/cpc-specialized-manifest.json
```

The regression script compares generated bytes and replays all 32 captured CPC
proofs through a registry selected from their source rule names. Checker tests
cover empty/unrelated registries, compiled source evaluation, wrong roots,
unsupported source rules, and invalid unused semantic certificates. Native
replay modes are `Specialized`, `SpecializedShared`, and `SpecializedReference`.
Generic source proofs are closed; complete checker proofs retain the documented
SMTCoq primitive-integer/proof-irrelevance baseline.

The proof-only `rules_correct` theorem conjoins all 87 generated correspondence
proofs. The assumption auditor checks this aggregate so it traverses their
shared compiler dependencies once. Individual correspondence proofs and their
kernel checking remain in place; no executable registry contains all rules.

Focused public-tactic profiles are exploratory: the fully compiled-helper
variant took 0.410/3.730/2.741 seconds on congruence/disjunctive bounds/inconsistent
bounds; the retained-helper variant took 0.394/3.647/2.499 seconds. Both passed
source/semantic/false-goal controls. These profiles did not establish a speedup
over the default checker. A matched full-workload comparison is required before
changing the default.
